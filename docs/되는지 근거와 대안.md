# 실물에서 되는가: 근거, 위험, 돌판 없는 대안

2026-11-18 기준. "부품만 사면 확실히 되나, 다 샀는데 안 되면 돌판으로 돌아가야 하나" 에 대한 답이다. 논문·공식 문서·사용자 보고·가진 기록·계산을 모았다. 계산 코드는 `sim/rt/place_followup.py`, 숫자는 `sim/pre/place.json`.

## 1. 한눈에

| 물음 | 답 |
|---|---|
| 부품만 사면 확실히 되나 | **'확실히'는 누구도 말할 수 없다.** 패널 수신기를 다섯 부분으로 나누면 넷은 다른 사람들이 실물로 해 본 것이다. 새로운 것은 하나다: **ESP32-C5 가 낸 CSI 세기만으로 위상을 되찾는 것.** 이것이 되는지는 관문 2 (그때까지 6.6만 원)에서 판가름 나고, 나머지 48만 원은 그 뒤에 산다 |
| 가장 큰 위험 | ESP32 의 CSI 세기가 패킷마다 흔들리는 것. 여러 칩을 같은 신호로 견준 2026년 논문에서 ESP32(S3)의 세기 잡음이 가장 컸다 (Intel AX210 의 약 9배). 다만 잡음이 고르게 퍼져 튀는 값이 드물었고, 흔들림의 큰 몫은 자동 이득 조절이었다. Espressif 가 이득을 고정하는 공식 부품을 냈고 C5 를 지원한다 |
| 안 되면 돌판으로 가나 | **가지 않는다. 받는 쪽만 바꾼다.** 패널(안테나 판), 스위치, 선, 기준 안테나는 그대로 쓴다. ① 이득 고정과 여러 번 재기 (0원) → ② 수신 체인이 둘인 Wi-Fi 카드(Intel AX210, 3~5만 원)를 미니 PC 에 꽂아, 한 체인은 기준 안테나, 다른 체인은 패널 스위치에 잇는다. 세기를 재지 않고 같은 패킷에서 둘의 비를 바로 얻는다. 계산으로는 ②도 지금 방식과 비슷하다: 사진 16장에서 기본 배치 88% (지금 방식 92%), 2.35 m 배치 95% (같다). 안테나마다 패킷 하나(16개)만 쓴 보수적인 계산이다. |
| 나쁜 것이 모두 겹치면 | 흔들림을 모두 겹쳐도 (이득 1 dB, 위상 단계 20도, 패킷 10% 가 2 dB 튐, 8비트) 사진 16장이면 거의 떨어지지 않는다: 기본 배치 92 → 91%, 2.35 m 배치 95 → 95%, 셋 97 → 97%. 사진을 모으는 것이 흔들림을 덮는다 |
| 돌판은 | receiver-legacy 에 보관만 한다. 대안 ②가 돌판보다 싸고 정확하다 |

## 2. 다섯 부분과 근거

| 부분 | 하는 일 | 다른 사람이 해 봤나 | 우리 쪽에서 남은 것 |
|---|---|---|---|
| 안테나 판 (CoreHW CHW1010-ANT2) | 패치 16개 가운데 하나를 스위치로 고른다 | 블루투스 방향 찾기용으로 파는 보드다. 만든 곳은 위치 10 cm 급이라 한다. 블루투스 방향 찾기 배열로 실내에서 잰 실험들의 방향 오차는 4~5도였다 (Lund 대학 2020, 이탈리아 CNR) | 블루투스는 한 패킷 안에서 안테나를 바꾼다. 우리는 패킷 사이에 바꾸므로 기준 안테나가 있다 |
| 기준 안테나 + 스위치 배열 | 패킷마다 흔들리는 수신기의 위상을 기준 안테나와의 비로 지운다 | Wi-Fi 에서 RF 스위치로 안테나를 늘리고 기준 채널과의 비를 쓴 연구가 있다 (Guan 외, IEEE JTEHM 2023; SWAN, MobiCom 2018) | 이 연구들은 수신 체인이 둘이다. 우리는 하나라 둘을 합쳐 세기를 잰다 (아래 줄) |
| 세기만으로 위상 (네 단계) | 기준과 안테나를 합쳐 0·90·180·270도에서 세기를 재면 복소 값이 나온다 | 위상 배열 보정의 오래된 방법이다 (REV, Mano·Katagi 1982; 네 단계 세기로 위상을 구하는 미국 특허 5,861,843). 단계가 정확히 90도가 아니어도 세 단계 이상이면 풀린다 (미국 특허 6,720,919). 세기만 재는 안테나 측정(간접 오프축 홀로그래피)도 같은 생각이다 | Wi-Fi 패킷처럼 세기가 패킷마다 다를 수 있는 신호에 쓴 기록은 찾지 못했다. **이것이 관문 2 다** |
| ESP32-C5 의 CSI | 패킷마다 서브캐리어 52개의 복소 값 | Espressif 는 CSI 에 C5 를 가장 좋은 칩으로 꼽는다. ACK 에서도 CSI 가 나온다는 사용자 보고가 있고 (ESP-IDF 이슈 19062), C5 두 개로 ACK 를 주고받는 다른 사용자 글은 'CSI 쪽은 문제가 없다' 고 적었다 (esp32.com) | Espressif 의 답은 아직 없다. 관문 1 |
| 카메라의 송신 세기 | 네 단계를 재는 동안 같은 세기로 보내야 한다 | - | 가진 카메라 기록: 이어진 패킷의 세기 차 가운데값 0.03~0.13 dB, 1 dB 넘게 뛰는 것 3~12% (버린다). 다른 카메라는 실물에서 |

## 3. 위험과 관문

| # | 위험 | 얼마나 그럴 법한가 | 어디서 보나 | 안 되면 (돌판 아님) |
|---|---|---|---|---|
| 1 | C5 가 ACK 의 CSI 를 내지 않는다 | 사용자 보고는 된다고 한다 | 관문 1 (3만 원) | 카메라가 보낼 때만 잰다. 사진을 16장 넘게 보내는 카메라는 어차피 보낸다 |
| 2 | 세기가 패킷마다 흔들린다 (자동 이득) | **가장 그럴 법하다** | 관문 1·2 | 이득 고정(`esp_csi_gain_ctrl`), 단계마다 세 번 재기, 튄 패킷 버리기. 그래도 안 되면 대안 ② |
| 3 | 선 넷의 위상이 90도 간격이 아니다 | 거의 틀림없다 (선 길이 오차) | 관문 2 | 문제 아니다. 실제 위상을 한 번 재 두고 쓴다. 계산에서 20도 틀려도 같았다 |
| 4 | 기준과 패널 안테나의 세기 차가 크다 | 거리에 따라 | 관문 2 | 기준 쪽에 고정 감쇠기 (3·6 dB) |
| 5 | 스위치를 바꾸는 순간이 패킷과 겹친다 | 가끔 | 관문 3 | 세기가 튄 패킷을 버린다 |
| 6 | 안테나 16개의 위상이 서로 조금씩 다르다 | 있다 (판·스위치) | 관문 4 | 한 번 재 둔 보정표. 계산은 보정하고 5도·0.5 dB 남는다고 뒀다 |
| 7 | 사진 한 장의 전송이 짧아 64패킷을 못 채운다 | 사진이 작고 빠르면 | 관문 3·4 | ACK 를 불러 이어 잰다. 대안 ②는 16패킷이면 된다 |

## 4. 돌판 없는 대안: 받는 쪽만 바꾼다

| 대안 | 바꾸는 것 | 값 (대략) | 패널·스위치·선 | 근거 | 처음 확인할 것 |
|---|---|---|---|---|---|
| ① 이득 고정 | ESP32-C5 설정 | 0원 | 그대로 | Espressif `esp_csi_gain_ctrl` (C5 지원, 고정 이득 모드) | 고정 이득에서 패킷을 놓치지 않는가 |
| **② 수신 체인 둘** | ESP32-C5 대신 Intel AX210 (2×2) + 미니 PC. 체인 하나는 기준 안테나, 하나는 패널 스위치 | 카드 3~5만 원, N100 미니 PC 15~25만 원 (허브를 겸한다). 첫 확인은 데스크톱에 M.2 변환 카드로 | 그대로 | AX210 의 CSI 잡음은 ESP32 의 약 1/9 (2026 견줌 논문). 기준 채널과의 비 (Guan 2023). PicoScenes 가 AX210 의 CSI 를 낸다 | 모니터 모드로 카메라가 보낸 프레임의 CSI 가 나오는가 (PicoScenes·FeitCSI). 노트북의 CNVi 카드(AX201·AX211)는 안 된다 |
| ③ 공유기 체인 | ASUS RT-AC86U 중고 + nexmon_csi. 체인 하나는 기준, 하나는 패널 | 중고 5~15만 원 | 그대로 | nexmon_csi 로 RT-AC86U 의 4체인 CSI 를 쓴 연구 (WiROS, SHARP; 5 GHz). 2.4 GHz(eth5) 로 쓰는 사용자 안내도 있다 | 2.4 GHz 쪽에서 체인마다 CSI 가 나오는가 |
| (참고) ESPARGOS | ESP32 여덟 개를 위상 맞춘 배열 | 팔지 않는다 (EU 연구실·기업에만, 아주 적게) | - | - | - |
| (참고) esp-crab | C5 둘을 같은 수정 발진기로 | 회로가 공개되지 않았다 | - | - | - |
| (참고) 2채널 SDR | bladeRF 2.0 micro 등 | 150만 원 안팎 | 그대로 | - | 예산 밖 |

②가 가장 확실하다. 세기를 재지 않으므로 위험 2·3·4 가 없어지고, 같은 패킷에서 기준과 안테나를 함께 받으므로 카메라의 송신 세기가 바뀌어도 상관없다. 대신 허브가 라즈베리파이에서 미니 PC 로 바뀐다.

## 5. 계산: 대안과 나쁜 경우

정확히 / 옆자리까지 (%). 교실 40석, 새 카메라 1,200대, 사람 자세가 다른 32순간 (흔들림을 겹친 것은 16순간). 배치는 [배치 계산](배치%20계산.md)의 것.

| 받는 쪽 | 사진 | 지금 거는 곳 | 기본 배치 (손이 닿는 높이) | 두 곳 2.35 m | 세 곳 |
|---|---|---|---|---|---|
| 지금 방식 (세기 네 단계, 흔들림 보통) | 1장 | 60 / 86 | 61 / 88 | 67 / 90 | 71 / 91 |
| | 16장 | 88 / 97 | 92 / 98 | 95 / 99 | 97 / 99 |
| 지금 방식, 나쁜 것이 모두 겹침 | 1장 | 57 / 85 | 59 / 88 | 64 / 90 | 69 / 92 |
| | 16장 | 85 / 96 | 91 / 99 | 95 / 99 | 97 / 100 |
| 대안 ② 수신 체인 둘 (안테나마다 패킷 하나) | 1장 | 58 / 86 | 57 / 87 | 66 / 91 | 67 / 90 |
| | 16장 | 86 / 97 | 88 / 98 | 95 / 99 | 95 / 99 |

- 흔들림을 모두 겹쳐도 사진 한 장일 때 2~4점, 16장일 때 0~3점 떨어진다. 위상 단계가 20도 틀리거나 CSI 를 8비트로 받는 것은 실물에서 그럴 만한 값의 위쪽이다.
- 대안 ②는 계산에서 패킷을 안테나마다 하나만 썼다 (16개. 지금 방식은 64개). 그래도 비슷했다. 같은 수의 패킷을 쓰면 잡음이 더 줄어든다.
- 어느 받는 쪽이든 지금 거는 곳의 사각지대(첫째 줄 창 쪽)는 남는다. 사각지대는 받는 쪽이 아니라 거는 곳의 문제다.
