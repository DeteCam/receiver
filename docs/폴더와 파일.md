# 폴더와 파일

저장소 `receiver` 의 모든 폴더와 파일이 무엇인지 적었다. 처음이면 [README](README.md)의 순서대로 문서를 읽고, 코드를 고칠 때 여기서 찾는다.

## 한눈에

```
receiver/
├── README.md            첫 화면
├── docs/                문서 (옵시디언 볼트의 DeteCam 폴더)
│   ├── images/          그림
│   └── simulator/       3축 화면 (깃허브 Pages)
├── cad/                 3D 모델 코드
│   ├── model/           치수(p2.py)와 부품 모양
│   ├── export/          STL·마커 내보내기
│   ├── checks/          겹침, 나사, 조립, 걸림 검사
│   ├── analysis/        무게, 힘, 튼튼함, 넘어짐
│   ├── figures/         그림 만들기
│   ├── slicing/         Bambu Studio 슬라이싱과 G코드 검사
│   ├── results/         검사·해석 결과 (json)
│   └── assets/          그림 재료
├── stl/                 출력할 부품
├── print/               출력 파일: gcode/ (바로 출력), project/, preview/
├── marker/              AR 마커
├── firmware/            수신기 코드: pi/ core/ host/ tests/
├── sim/                 시뮬레이션: direction/ location/ identify/
│   └── em/              전파 계산: model/ studies/ tools/ figures/ tables/ fdtd/
└── console/             3축 화면 원본: src/ dist/
```

**규칙.** 코드는 하는 일끼리 폴더로 묶었다. 계산 결과(json)는 그것을 만든 코드 가까이에 둔다 (`cad/results/`, `sim/` 의 각 폴더). 그림은 모두 `docs/images/` 에 모인다. 폴더 이름은 영어, 문서와 그림과 출력 파일 이름은 한글이다.

## 저장소 맨 위

첫 화면(README), 그리고 아래 폴더들

| 파일 | 하는 일 |
|---|---|
| `.gitattributes` | 줄바꿈과 이진 파일 표시 |
| `.gitignore` | 깃에 넣지 않을 것 (다시 만들 수 있는 큰 중간 파일, 옵시디언 설정) |
| `README.md` | 첫 화면: 생김새, 시뮬레이터, 개요, 폴더 |

## `docs/` — 문서와 그림

만들 때 읽는 문서. 옵시디언 볼트의 `DeteCam` 폴더가 바로 이 폴더다. 깃허브 Pages 로도 열린다 (시뮬레이터)

| 파일 | 하는 일 |
|---|---|
| `.nojekyll` | 깃허브 Pages 가 파일을 그대로 보여 주게 하는 표시 |
| `README.md` | 문서 모음의 첫 장 (노트 목록과 설계 요약) |
| `index.html` | 깃허브 Pages 첫 주소. 시뮬레이터로 넘어간다 |
| `네 단계 검토.md` | 탐지 → 판별 → 위치 측정 → 표시, 곳별 결과 |
| `부품표.csv` | 부품표를 표 계산 프로그램용으로 |
| `부품표.md` | 출력 부품, 살 것, 연장 |
| `비콘 검토.md` | 아무도 시청하지 않는 핫스팟 카메라를 비콘으로 찾을 수 있나 (손으로 쓴 노트) |
| `설계 검토.md` | 왜 이렇게 만들었나: 오차, 판 모양, 자기 부품의 영향, 볼트 고정과 치수, 무게, 넘어짐, 튼튼함, 검사, 실물에서 확인할 것 |
| `시뮬레이션 화면.md` | 3축 화면을 여는 법과 시뮬레이션 결과 그림 |
| `유용성 근거.md` | 왜 필요한가: 범죄 통계, 설치형 몰카가 대부분 Wi-Fi 인 근거, 생중계 사건, 기존 탐지의 한계, 예상 질문과 답 (손으로 쓴 노트) |
| `조립 안내.md` | 살 것, 출력, 조립(전부 나사로), 배선, 처음 켜기, 폰으로 재기. 만들 때는 이것부터 |
| `체크리스트.md` | 지금부터 할 일 (눌러서 체크) |
| `폴더와 파일.md` | 이 문서: 모든 폴더와 파일이 하는 일 |
| `혼자 동작.md` | 수신기 코드: 설치, 폰 화면의 단추, 주소(API), 장치 없이 돌려 보기 |

## `cad/model/` — 모델 (치수와 부품 모양)

다른 폴더의 스크립트가 모두 이 폴더의 모듈을 쓴다

| 파일 | 하는 일 |
|---|---|
| `cadlib.py` | 모양을 만드는 작은 도구 (상자, 원기둥, 빼기, 돌리기) |
| `p2.py` | 치수: 머리, 요크, 받침, 판, 판 틀, 기어, 나사 자리 등 거의 모든 값. 고칠 것은 여기서 |
| `params.py` | 파이와 모터의 치수 (공식 도면, 안테나 자리) |
| `parts.py` | 사는 부품의 모양 (파이, 모터, 드라이버 보드)과 처음 판의 부품 일부 |
| `parts2.py` | 부품 모양 (머리, 요크, 받침, 회전 막대, 판 틀 등)과 조립 자세 |
| `paths.py` | 결과를 어디에 쓰는지 (저장소 배치와 작업용 배치) |

## `cad/export/` — 내보내기

STL, 마커, 3D 보기 파일을 만든다

| 파일 | 하는 일 |
|---|---|
| `export2.py` | 부품을 출력 방향으로 눕혀 STL 로 내보내고 다시 읽어 검사한다 (닫힘, 한 덩어리, 처짐면) → `stl/`, `results/parts.json` |
| `export_assembly.py` | 수신기 전체를 3D 보기용 STL 한 장으로 → `docs/images/수신기_3D.stl` |
| `marker.py` | AR 마커 종이(PDF, PNG)와 마커 좌표를 만들고 다시 읽어 본다 → `marker/` |

## `cad/checks/` — 검사 (겹침, 나사, 조립, 걸림)

모델이 실제로 조립되고 움직이는지 계산으로 본다. 결과는 `results/`

| 파일 | 하는 일 |
|---|---|
| `audit_assembly.py` | 조립 순서대로 부품을 밀어 넣는 길이 비어 있는지 |
| `audit_motion.py` | 기어 물림, 멈춤턱, 자세별로 판과 몸체 사이 틈 |
| `audit_screws.py` | 나사 하나하나: 구멍 지름, 물리는 길이, 끝이 나오는지, 머리, 드라이버가 들어갈 길 |
| `audit_sweep.py` | 판을 돌리며 요크·받침과의 틈을 촘촘히 (끄덕임 1°, 판 3°, 축 흔들림까지). 30분~1시간 |

| `check2.py` | 세 관절 전 범위에서 부품끼리 겹치는 곳 (가만히, 움직이며) |
| `check_extra.py` | 나사 머리, 볼트, 동전까지 넣은 겹침. 크기가 다른 버튼 모듈과 드라이버 보드도 들어가는지 (`--variants` 는 이것만) |
| `dongle_gap.py` | USB 동글 두 개의 틈 (서로, 요크와, 받침과) |
| `room_check.py` | 부품이 들어가는 자리와 여유 (파이, 드라이버, 배터리, 플러그), 전선 길이 |
