# 001 방향 찾기

## 배경

안테나 둘레로 알루미늄 판을 돌리면, 판이 카메라와 안테나 사이에 올 때 받는 신호가 달라진다. 판의 각도마다 신호 세기를 적은 것이 **신호 곡선**이고, 이 곡선에서 카메라가 있는 방향을 읽는다.

처음에는 곡선에서 "가장 약한 곳(골)"을 찾았다. 가리는 것이 없는 넓은 곳에서는 맞지만, 방 안에서는 벽·천장·사람에서 튕긴 전파가 섞여 골이 엉뚱한 곳에 생긴다. 전파 경로 계산으로 본 40명 교실에서 골 찾기는 자리를 맞힌 비율이 6% 로 찍는 것과 같았고, 직접 오는 전파 하나만 있는 이상적인 경우에도 방향 오차 가운데값이 45~55° 였다 ([sim/rt](../../sim/rt/README.md)).

## 요구사항

| 번호 | 내용 |
|---|---|
| FR-1 | 스캔 한 번(판 한 바퀴)의 패킷들로 5° 간격의 신호 곡선을 만든다. 부반송파 가운데 판에 따라 가장 크게 변하는 것들을 골라 쓴다 |
| FR-2 | 방향은 **곡선 전체를 기준 곡선과 견주어** 읽는다. 기준 곡선은 "카메라가 이 방향에 있으면 곡선이 이렇게 생긴다"를 방향마다 모은 표다 |
| FR-3 | 카메라 안테나가 누운 방향(편파)을 모르므로 여러 가정을 두고, 한 곳에서 잰 스캔들이 같은 가정을 쓰게 한다 |
| FR-4 | 결과는 방향 하나가 아니라 **방향마다의 가능성**으로 낸다. 위치 추정(002)이 이것을 곱해 쓴다 |
| FR-5 | 기준 곡선은 처음에는 전자기 계산(NEC2)으로 만든 표를 쓰고, 실물로 잰 곡선으로 바꿀 수 있다 (보정) |
| FR-6 | 머리를 숙인 각도와 받침 방향을 곡선과 같이 적어, 위아래 방향까지 구분한다 |
| NFR-1 | 한 곳의 18번 스캔을 라즈베리파이 3B+ 에서 10초 안에 계산한다 |

## 수용 기준

- 직접 오는 전파 하나만 있는 계산 자료에서 방향 오차 가운데값 7° 이하 (지금 2.9~6.9°).
- 실물: 가리는 것 없는 3m, 0°·45°·90°·135° 각 3회에서 오차 가운데값 15° 이하 (시스템 목표 G-3).
- `firmware/tests` 의 곡선 자료로 돌린 결과가 바뀌지 않는다.

## 범위 밖

- 여러 곳의 결과를 합치는 일 (002). 카메라를 고르는 일 (004).

## 확인할 것

- 실물 곡선이 계산한 기준 곡선과 얼마나 닮았는지. 계산에서 기준 곡선이 실물과 조금 다를 때(머리만 넣고 계산한 표) 자리 맞힘이 90% → 84% 였다 (시도 횟수에서 오는 흔들림 안). 이 정도 차이는 버티지만, 실물 곡선이 표와 얼마나 다를지는 재 봐야 안다.
