# 004 탐지 (의심 기기 고르기)

## 배경

위치를 재려면 먼저 어느 기기가 카메라인지 골라야 한다. 카메라가 어느 Wi-Fi 에 붙었는지, 이름이 무엇인지는 모른다. 공중에 오가는 Wi-Fi 신호의 겉(누가 누구에게, 얼마나, 언제)만 보고 고른다. 내용은 암호화되어 있어 보지 않는다.

## 요구사항

| 번호 | 내용 |
|---|---|
| FR-1 | 탐지 동글로 2.4·5GHz 채널을 돌며 기기마다 보낸 양, 올리는 비율, 끊김 없이 이어지는지, 언제 나타났는지를 모은다 |
| FR-2 | 증거마다 점수를 주고 더해 **의심 점수**를 낸다. 모드를 나누지 않는다 (몰카·시험장 같은 흐름) |
| FR-3 | 점수에는 근거 한 줄이 붙는다 ("올리는 양이 받는 양의 20배", "시험 시작 뒤에 나타남") |
| FR-4 | 필요할 때만 사람에게 확인을 시킨다: 걷기·멈추기에 전송량이 따라 변하는지 (판별) |
| FR-5 | 고른 기기를 패널의 ESP32-C5 로 짧게 찔러(데이터 없는 프레임) 응답(ACK)을 받고, 그 응답의 CSI 세기를 006(패널)에 넘긴다 |
| FR-6 | 폰이 여러 대 있는 교실에서도 폰 핫스팟과 그 핫스팟으로 올려 보내는 기기를 가린다 |
| FR-7 | 기기 표에 들린 채널과, 패널로 위치를 잴 수 있는지(`locate`)를 싣는다. 두 대역 판([008](../008-dual-band-panel/spec.md))의 위상 단계를 5 GHz 채널에서 재기 전에는 2.4 GHz 1~13번만 참이고 5 GHz 기기는 탐지와 판별까지만 한다. 보정이 되면 5 GHz 채널도 참이 된다 |
| FR-8 | (확장 과제) 허브의 내장 블루투스로 BLE 광고를 듣고, 근처에서 광고하는 블루투스 기기의 수와 새로 나타난 기기를 `GET /api/status` 의 `ble` 로 낸다 (앱 001). 자리는 재지 않는다. 블루투스 기기는 사람을 의심하는 근거로 쓰지 않는다 (보청기 · 연속혈당측정기 같은 의료 기기도 BLE 를 낸다). 주소는 세션 안에서만 쓰고 저장하지 않는다 |
| NFR-1 | 처음 결과까지 30초. 5GHz 까지 들으면 첫 바퀴만 약 20초 더 |

## 수용 기준

- 검사 자료(`firmware/tests`)에서 카메라가 의심 1순위. 폰 40대가 있는 시험장 자료에서 잘못 올리는 일 5% 이하.
- 실물: 시스템 목표 G-1, G-2.
- BLE (확장 과제): 광고하는 기기(폰, 이어폰, 스마트워치) 다섯 대를 켜고 끄며 1분 안에 대수가 따라 바뀐다. Wi-Fi 엿듣기가 느려지지 않는다.

## 범위 밖

- 프레임 내용 풀기. 찾은 기기의 통신을 끊거나 방해하기.
- 블루투스 기기의 자리, 블루투스 클래식 (Ubertooth 가 따로 든다).

## 확인할 것

- **ESP32 의 ACK CSI.** 제조사 설정에 ACK 를 내보내는 항목(`dump_ack_en`)이 있다는 것까지 확인했다. 실제로 값이 나오는지, 초당 몇 개가 나오는지는 보드를 받아 재야 한다. 안 되면 FR-5 를 빼고 카메라가 스스로 내보내는 영상 프레임만으로 잰다.
- 아무도 보고 있지 않아 조용한 카메라 ([비콘 검토](https://github.com/DeteCam/docs/blob/main/research/비콘%20검토.md)).
